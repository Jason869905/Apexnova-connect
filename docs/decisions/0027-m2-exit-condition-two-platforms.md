# 0027 M2 的平台退出条件改为两个平台

- 状态：已接受
- 日期：2026-09-13
- 阶段：M2 Multi-Agent Alpha（回溯修订；提出于 M5 期间）
- 前置：[ADR 0024](0024-narrow-platform-claims.md) 把四个 Integration 的平台声明收窄为 Windows/Linux，并写明它**没有**决定 M2 的退出条件
- 结论：M2 第五条退出条件由「三个平台」改为「两个平台（Windows、Linux）」；macOS 凭据后端同时改为**默认拒绝**

## 1. 决策

M2 退出条件原文：

> 三个平台的凭证和恢复流程通过真实环境测试。

改为：

> **两个平台（Windows、Linux）**的凭证和恢复流程通过真实环境测试。

范围项「macOS Keychain 后端与三平台验收」同时标注结局：后端已实现但从未在真机验证，macOS 已于 [ADR 0024](0024-narrow-platform-claims.md) 退出支持范围。

## 2. 这不是把要求改到现状上——判据是「谁先动」

[ADR 0012](0012-region-is-the-wrong-requirement.md) 与 [ADR 0022](0022-m5-midpoint-review.md) 都否决过「把要求改到做不到的现状上」。本条必须过同一道关，而它过关的方式是一个可核对的时间顺序：

**产品声明先变，退出条件后跟。** [ADR 0024](0024-narrow-platform-claims.md) 收窄 macOS 是在 2026-09-12，理由与 M2 无关——[ADR 0023](0023-integration-status-ladder.md) 把「声称即有据」做成受检条件，四个 manifest 当场全部不合格，出路只有拿到实机或收窄声明。**那时没有人在问 M2 能不能关。**

于是今天的局面是：**一条退出条件要求在真实环境验证一个产品已经不再交付的平台。** 那不是高标准，是没有对象——与 ADR 0012 判定「区域不是约束、是测量条件」同形，区别只在这里错的是范围而不是类别。

反过来说，若当初是为了关 M2 才去收窄 macOS，这条就不该通过。**区别不在措辞，在顺序**，而顺序是可查的：ADR 0024 在前，且它自己写明「没有决定 M2 的退出条件」。

## 3. 代价：macOS 是没有了，不是推迟了

写清楚，不含糊：

- **不再有 macOS 支持**，也没有恢复它的计划。要恢复，需要实机、需要重采证据（[ADR 0023](0023-integration-status-ladder.md) 第 1 条会当场拒绝没有证据的声明），是一次新的决定；
- **凭据后端仍在代码里**，但从今天起**默认拒绝**，见第 4 节；
- M2 自开阶段起唯一未满足的就是这一条。改掉它之后 M2 的五条全部满足——**但这不等于 M2 已关闭**，见第 5 节。

## 4. 这条决定有一半是代码

只改文档会留下一个本项目反复在抓的形状：**声明说不支持，代码照常服务。**

`createDefaultCredentialStore` 在 `darwin` 上会选中 `MacOsKeychainBackend`，而该后端**只跑过 mock command runner，从未对过真实 Keychain**。收窄声明之后仍让它默认服务，等于在一个我们不再声称支持的平台上，让未验证的实现继续接管凭据这条最敏感的路径，而用户得不到任何信号。

因此改为**默认拒绝**，报 `UNSUPPORTED_PLATFORM` 并说明：后端存在、从未验证、可用 `APEXNOVA_ALLOW_UNVERIFIED_MACOS=1` 显式启用，启用后它报告的一切都按未验证对待。

两点取舍写明：

- **拒绝而不是告警**，因为它处理的是秘密。一次半成功的 keychain 写入会丢失或损坏凭据，而 stderr 上的一行告警不是同意；
- **保留 opt-in 而不是删除后端**，因为「不支持」与「禁止尝试」是两件事。删掉它会让任何想在 Mac 上试的人无路可走，而那不是这条决定要达到的效果。

## 5. M2 其余四条的核对，以及为什么本记录不关闭 M2

既然改动的是最后一条未满足的，其余四条就必须一并核对，否则「五条全满足」只是推论：

| 退出条件 | 核对 |
| --- | --- |
| 四个 Agent 使用同一套发现、计划、验证和恢复生命周期 | 满足。四个都通过 `describeIntegrationContract`，该套件正是按这条写的 |
| 产品特有逻辑没有进入 `packages/core` 和 `apps/cli` | 满足。`packages/core/src` 检索四个产品名**零命中**；`apps/cli` 只有两处出现产品名——`integrations.ts` 的注册表组装，以及 `apexnova opencode` 这个 v0.1 遗留别名（它转发到通用 `run` 路径，不含任何 OpenCode 专有逻辑，且在 [CLI 规格](../cli-spec.md) 里是写明的兼容承诺） |
| 未知配置格式不会被猜测修改 | 满足。契约套件对每个不支持版本／损坏配置的 fixture 断言「拒绝改写」 |
| 社区能够独立实现只读 Detection Integration | 满足。`integrations/_template` 提供模板并自带契约测试。**限制写明：至今没有外部实现过，这条验的是路径存在，不是有人走过** |
| 两个平台的凭证和恢复流程通过真实环境测试 | 满足。Windows 上 OpenCode/Codex/Claude Code、Linux 上 Hermes 与 OpenCode 均完成过完整生命周期实测，记录见 [Hub 联调清单](../hub-h1-integration-checklist.md) |

**五条都满足了。但本记录不关闭 M2。** 里程碑关闭在本项目里一直是独立一条记录（[ADR 0006](0006-m3-closure.md) 关 M3、[ADR 0015](0015-m4-closure.md) 关 M4），且关闭要连带回答「M2 期间的挂账与限制各自去了哪里」——比如上表最后一行那条「没人走过」。把关闭塞进一条修订退出条件的记录里，会让它没有被单独审视过。
