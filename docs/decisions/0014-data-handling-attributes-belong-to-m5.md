# 0014 数据处理属性由 Hub 后续提供，隐私约束移到 M5

- 状态：已接受
- 日期：2026-09-11
- 阶段：M4 Match Beta（目标版本 `v0.4`）
- 前置：[ADR 0013](0013-m4-second-review.md) 判定 12J 是该条退出条件唯一的外部依赖
- 影响：M4 的约束退出条件去掉「隐私」，M5 增加一条；需求 12J 选定形状并记为遗留
- **后续：本记录给 M5 增加的那条退出条件已由 [ADR 0022](0022-m5-midpoint-review.md) 第 3.1 节撤销**——理由是它指错了责任方：Connect 侧已做完且验证过，缺的是只有 Hub 能发布的事实。**需求 12J 不受影响，仍在 Hub 需求清单上**

## 决策

**[需求 12J](../apexnova-ai-hub-requirements.md) 采纳第 2 个形状：Hub 后续为每个 Deployment 发布可比较的数据处理属性**——数据处理所在区域／司法辖区、是否用于训练、是否存在子处理方等。不要求披露上游运营方身份。

**该能力记为遗留，不阻塞 M4。** M4 的约束退出条件因此从「模型白名单、预算和隐私约束」变为「模型白名单和预算」，隐私约束移入 M5。

## 理由

与 [ADR 0012](0012-region-is-the-wrong-requirement.md) 移除「区域」不同，这条**不是选错了对象**。隐私是真实需求，没有替代表达方式，措辞和验证标准都不下调——移的是阶段，不是要求。

形状选第 2 个，因为它同时满足两边：抽象掉上游本来就是这个平台在卖的东西，Hub 不必因为一条约束而披露运营方身份；而属性是可比较的，因此约束可以针对属性而不是针对名字，Connect 侧的过滤器不需要知道对方是谁。

移到 M5 的结构性理由与 [ADR 0008](0008-non-apexnova-candidates-belong-to-m5.md) 同型：**Connect 侧该建的已经建好了，缺的只有一个上游字段。** `--exclude-publisher` 已经证明整条路径成立——过滤语义、「证明不了就不通过」的规则、输出里的排除理由都在，换一个属性来源即可。而数据处理属性与 M5 范围里的路由约束是同一类东西：都要求 Connect 能对「请求实际去了哪里、由谁处理」作出可执行的判断。

## 必须写明的代价

[ADR 0011](0011-m4-milestone-review.md) 留过一句防线：再次移动这条要求需要比 ADR 0008 更强的理由，而不是更弱的。严格地说「区域」是被移除而非移动，因此隐私是本条要求第一次被移动；但**这条退出条件已经第二次少掉一个组成部分**。

所以要说清楚：**M4 最终被判定时所依据的，不是这条退出条件当初写下的样子。** 原文是「模型白名单、预算、区域和隐私约束」四项，M4 收口时实际验收的将只有前两项——区域被判定为选错对象而移除，隐私移到 M5。这是本记录的代价，写在这里而不是留给收口时再发现。

对应地，**M5 收口时这条不得再移动**，与 ADR 0008 那条并列：两条都已用掉各自的推迟理由。

## 后果

- M4 的约束退出条件变为两项，均已实现且可用（白名单；预算——[需求 12H](../apexnova-ai-hub-requirements.md) 已交付，`--max-price` 实测在筛）。**该条退出条件因此满足**；
- **M4 仍不关闭**，但剩下的两件都是我们自己的（[ADR 0013](0013-m4-second-review.md) 第 5 节）：Recommendation 的有效期未计入分时价格，以及 launcher 静默错配的根因未查实。M4 的关闭不再依赖任何外部交付；
- `recommend --exclude-publisher` 保留。它是发布方过滤，不是数据处理约束，[`cli-spec.md`](../cli-spec.md) 与 [ADR 0010](0010-m4-constraint-exit-condition-status.md) 已经把两者分开写明，不得在文案上合并成「隐私」——否则用户会以为设了它就满足了合规要求；
- 12J 在需求文档中保留并标注选定形状与遗留状态。Hub 交付后 Connect 实现属性过滤并实测，那是 M5 的验收项。

## 被否决的选项

- **把 M4 的「隐私约束」改写成「发布方隐私约束」，就地宣布满足。** 那是把措辞改到现状上——ADR 0012 已经否决过同一种做法，而且这次更糟：发布方过滤回答不了合规问题，改写措辞等于让一份不能回答的东西冒充能回答。
- **等 Hub 交付再关 M4。** M3 与 M4 都验证过「先本地、后 Hub」，让一个里程碑吊在跨仓交付上，与那条结论相反。
- **要求 Hub 披露上游运营方身份。** 平台的价值之一就是抽象掉上游；属性形状能达到同样的执行效果，没有理由把更强的披露作为前提。
