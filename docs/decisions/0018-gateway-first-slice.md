# 0018 Gateway 首个切片：只做忠实转发与逐请求归属

- 状态：已接受
- 日期：2026-09-11
- 阶段：M5 Reliable Provider Routing（目标版本 `v1.0`）
- 前置：[ADR 0016](0016-m5-scope-and-first-batch.md) 把 Gateway 排除在首批之外；[ADR 0017](0017-m5-first-batch-review.md) 记录了首批留下的缺口

## 背景

到目前为止 Connect 不在请求路径上：它写配置、签发凭据、启动进程，请求由 Agent 直接发往 Hub。Gateway 改变这一点，这是 M5 形态上最大的一次变动。

[ADR 0017](0017-m5-first-batch-review.md) 留下的一条缺口正好指向它：**launcher 的归属是时间窗而不是精确匹配**。`verify` 能按 `requestId` 精确对账，因为它自己发那一个请求；launcher 只能在小时桶上做前后差，同一账号在别处并发使用时会把别人的请求算进来。这不是归属逻辑写得不好，是**站在请求路径之外就只能看到这些**。

## 决策

1. **首个切片只做两件事：忠实转发，和逐请求归属。** 不做路由选择、不做故障转移、不做重试、不做 Circuit Breaker、不做缓存。

2. **忠实的定义要写死，因为它是这个切片唯一的正确性标准。** Gateway 对 Agent 与 Hub 之间的语义**不作任何改动**：请求体逐字节转发，响应体逐字节回传，流式事件的顺序与边界不得重组，`X-Apexnova-Request-Id` 等头按原样传递，错误状态码与错误体原样返回。**任何"顺手规范化"都是缺陷**——M3 花了整个阶段证明流式顺序与错误语义是 Agent 会踩到的东西。

3. **协议知识不进 Gateway。** `packages/protocols` 已经承载协议差异，Gateway 只做字节与连接层面的转发。一旦 Gateway 开始理解请求体，它就成了协议语义的第二处实现，而两处实现会各自漂移——这个项目已经在 subject 身份上付过三次这个代价。

4. **凭据边界因此收紧，这是顺带的收益而不是目标。** 今天 Hub 的 runtime credential 由 launcher 注入 Agent 进程的环境变量；有了 Gateway，Agent 只需要一个**本机回环地址加一枚本地令牌**，Hub 凭据只存在于 Gateway 进程内。Agent 进程、它的插件、它写的日志因此都接触不到 Hub 凭据。

   但要写明代价：**多了一个持有凭据的进程**，它的生命周期、绑定地址与本地令牌的存放都必须当作凭据来对待，不能因为"只是本机"就放松。仅监听回环，不监听任何外部地址。

5. **不做自动重试，并且这是有意的。** M5 的退出条件之一是「Provider 故障不会造成工具副作用请求的自动重放」。首个切片的做法是**根本不重试**：转发失败就把失败如实交给 Agent。重试语义要在知道哪些请求带工具副作用之后才谈，而那是后面的切片。

6. **归属在这里变成精确的。** Gateway 看得见每一个请求与它的 `requestId`，因此审计的 `attributed` 记录可以逐请求而不是按时间窗。[ADR 0017](0017-m5-first-batch-review.md) 记的那条缺口由此关闭——**这也是先做这个切片而不是先做路由的理由**：它修掉一个已知的错误来源，而不是增加一个新的。

7. **Gateway 是可选的，默认不开。** 现有的直连路径不动。一个刚进入请求路径的组件，不应该在同一次变更里成为唯一路径——出问题时要能立刻退回去，而退回的方式是不启用它，不是回滚代码。

## 首个切片的验收目标

- **忠实**：同一组请求经由 Gateway 与不经由 Gateway，Agent 侧观察到的响应体、流式事件顺序与错误状态一致。能力套件的离线回放夹具可以直接用来证明这一点；
- **精确归属**：一次经 Gateway 的运行，审计里每个请求都有自己的 `requestId`，不再是时间窗差值；
- **凭据不外泄**：Agent 进程的环境里没有 Hub 凭据；Gateway 只监听回环；
- **失败如实**：上游失败按原样返回，不重试、不改写。

## 后果

- 交付形状是 `packages/gateway`（今天只有一个 README 占位）加 CLI 的启用开关；
- `run` 在启用 Gateway 时改为把 Agent 指向本机地址，这会改变 Integration 写入的配置内容（`baseURL`），因此**每个 Integration 都要重新做一次端到端验收**，不能只验 OpenCode；
- 直连路径继续存在，两条路径的归属精度不同，审计记录必须能看出是哪一条——否则读日志的人会把时间窗的近似当成精确；
- Circuit Breaker、受控选择、故障转移都在这个切片之后，且各自需要自己的范围决定。

## 被否决的选项

- **首个切片就带上路由选择或故障转移。** 那会让第一次出问题时分不清是转发错了还是选择错了。先证明「原样转发」成立，再谈「换一个上游」；
- **让 Gateway 解析并重写请求体**（例如统一模型名）。那是把协议语义放进第二个地方，而 `packages/protocols` 已经是第一个；
- **默认启用 Gateway。** 一个刚进入请求路径的组件默认承担全部流量，等于把回退路径一起去掉。
