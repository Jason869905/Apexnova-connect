# 0020 Gateway 这一批的收尾：仍然保持可选

- 状态：已接受
- 日期：2026-09-12
- 阶段：M5 Reliable Provider Routing（目标版本 `v1.0`）
- 前置：[ADR 0018](0018-gateway-first-slice.md) 定义切片、[ADR 0019](0019-gateway-first-slice-review.md) 评审并列出缺口
- 结论：**缺口清完六条、剩两条**；**不转为默认**，并写明要满足什么才转

## 1. ADR 0019 列出的缺口，逐条结清

| 缺口 | 状态 |
| --- | --- |
| 失败注入 | **已补**：上游不回响应头、流式中途断裂、客户端中途离开、长流不被误杀，四条各有注入 |
| 超时 | **已补**：只管到响应头（默认 60 秒），流式开始后不设限；超时 504、`retryable: false`、只尝试一次 |
| 忠实性的强证据 | **已补**：能力套件对同一份回放夹具跑两遍（直连 / 经 Gateway），逐项判定相同。两处边界写明——`auth.endpoint-reachable` 按构造无法经 Gateway 提问；回放不重现块间时序 |
| `path` 与 `durationMs` 入审计 | **已补**，并更正了 ADR 0019 对它的定性：它是**这条路由的逐请求明细**，不是 Operational Evidence |
| 长会话 | **做了近似**：多轮工具调用任务，4 个请求、23 秒，Agent 产出正确。**不是交互会话**，边界已写明 |
| 其余开关的复核 | **已补，且做的是结构性版本**：命令不读取的选项一律拒绝，而不是逐个复核那三次 |
| 并发验收 | **已补**：八个请求同时在途、上游反序应答，含变异检查 |
| 运行期内凭据不续期 | **已实现并已实跑验证**（[ADR 0021](0021-gateway-credential-renewal.md) 实现、[ADR 0030](0030-configurable-credential-lifetime.md) 验证）。**转默认的条件 1 已满足** |
| Claude Code 的 launcher | **已做（2026-09-13）**，见 [ADR 0029](0029-launch-must-honour-the-configured-file.md)。「环境所限」这个理由是错的。**转默认的条件 2 已满足** |

## 2. 「凭据不续期」要改一个说法：它不是没测到，是没实现

ADR 0019 把它列在「没有做到的」里，措辞像是一条测试缺口。核对代码后应当说得更准：`run --gateway` 在配置阶段把绑定赋值一次，之后**没有任何地方更新它**；Gateway 每次请求都去读那个绑定，读到的永远是同一枚凭据。

写成「未实现」而不是「未验证」，是因为这两者的下一步不同：前者要写代码，后者只要等时间。

> **同日更正。** 本节接着写的「我们已经知道它会失败」**是错的**，而且错在一个没有核对就当成确定的前提上：`run` 默认签发的是**永不过期的用户 key**，只有 `--rotating` 或 `connect` 才发 24 小时凭据，而 `run --gateway` 走的正是默认那条。所以当时**没有任何一条在用的路径会撞上到期**。改判「未实现」的方向是对的，论据只对了一半——我核对了绑定被赋值几次，没核对它是哪一种凭据。
>
> 续期现已实现，且 `--gateway` 改为一律签发短期凭据（那个理由消失了，见 [ADR 0021](0021-gateway-credential-renewal.md)）。**但第 3 节的条件 1 要求的是实现加上一次跨过到期的实跑，后者仍未发生，所以该条件仍不满足。**

## 3. 是否转为默认：不转

支持转的理由是实的：忠实性由套件证明、四类失败有注入、并发有证据、归属比直连精确、Agent 再也拿不到 Hub 凭据。

不转的理由更重：

- **剩下的两条缺口，恰好就是长时间运行才会暴露的那两条。** 默认启用意味着由用户先撞上「会话活过了凭据」；
- **本批四个缺陷里有三个是跑出来的**——`--gateway` 静默失效、`baseURL` 丢了路径、`close()` 卡在 keep-alive。而至今所有实跑都很短；
- **Claude Code 这条路径一次都没经 Gateway 跑过。** 四个 Integration 里有一个完全未知；
- **默认启用等于让「多一个持有凭据的进程」成为常态**，而不是用户明确选择的结果。

**转为默认需要三件事同时成立**，每一条都可核对：

1. ~~凭据在运行期内可续期，并且有一次跨过到期时间的实跑~~ **已达成（2026-09-13，[ADR 0030](0030-configurable-credential-lifetime.md) 第 5 节）**：3 分 19 秒的运行、120 秒寿命的凭据、两次续期、32 个请求分记三枚凭据。为此把凭据寿命做成可配置的，否则这条路径只能靠等满 23 小时；途中抓到三个缺陷，其中一个让**任何比 `--timeout` 更长的 `--gateway` 运行都无法续期**；
2. ~~Claude Code 经 Gateway 的端到端实跑通过（需要一个不以 Claude Code 为宿主的会话）~~ **已达成（2026-09-13，[ADR 0029](0029-launch-must-honour-the-configured-file.md)）**：括号里那个前提是错的——`--config` 指到隔离路径即可，本会话的配置全程未被触碰。但这条能成立依赖同日修掉的一个缺陷：`--config` 此前在启动这一步根本不起作用；
3. 至少一次真实的长交互会话，而不是自动任务的近似。

在此之前 `--gateway` 保持显式开启。**「能用」与「路径上的默认组件」是两个标准**，这一批把前者做实了，没有把后者也宣布掉。

> **2026-09-13 状态**：条件 1 与条件 2 均已达成（见上）。**条件 3（一次真实的长交互会话）仍未达成**，因此 `--gateway` 仍不设为默认。这一条无法由自动任务替代——[ADR 0019](0019-gateway-first-slice-review.md) 第 5 节已经否决过一次近似，它要的是人类回合、长空闲与数小时时长。**而坚持这一条现在有了更硬的理由**：本记录列的三条门槛里，前两条各自在被真正执行时都揪出了缺陷（[ADR 0029](0029-launch-must-honour-the-configured-file.md) 两个、[ADR 0030](0030-configurable-credential-lifetime.md) 三个），没有一个是测试发现的。把第三条也走一遍之前，没有理由相信它会例外。

## 4. 这一批验证与推翻了什么

**验证的：**

- **默认关闭是本切片最值钱的决定**（[ADR 0018](0018-gateway-first-slice.md) 决策 7）。四个自造缺陷有三个在真实运行中暴露，而直连路径始终可用，因此每次都能立刻退回去；
- **失败注入值得单独算一笔**。第四个缺陷不是跑出来的，是**写注入用例的过程本身**发现的：流在中途断裂时，外层 catch 在响应头已经发出之后仍然往流里追加了一个 JSON 错误体。它既不会出现在正常运行里，也不在此前任何一条测试的射程内——直到有人专门去制造"上游在半途死掉"。
- **先转发、不做路由**（决策 1）：Hermes 的既有协议错配被 Gateway 变成「11 个被拒请求，逐个点名」，直连则把同一次全败的运行报成「已确认计费 2 次」。这个对比本身就是这条决策的回报。

**推翻的：**

- **「测试覆盖足够就可以放心接进请求路径」**。本批四个缺陷，**没有一个是既有测试发现的**：三个由真实运行撞出（一个读了未赋值变量的条件、一处只换 origin 不换路径的 URL 拼接、一个等待客户端礼貌关闭的 `close()`），一个由新写的失败注入发现（一个在头已发出后仍试图写错误体的 catch）。

  它们分成的这两类正好说明了缺的是什么：前三个**只在真实客户端面前才成立**，后一个**只在上游反常时才成立**。此前的测试两样都不制造——它用自己的 fetch 打一个总是正常应答的替身；
- **「逐个复核已知开关」是够的**。三次同形失败之后，结构性的那一版（命令不读的选项一律拒绝）当场就抓到了 `balance --max-price` 这类此前无人注意的例子。

## 5. 下一步

Gateway 这条线到此为止不再扩张。按 [ADR 0016](0016-m5-scope-and-first-batch.md) 的顺序，接下来才是 Circuit Breaker 与受控选择——但**它们都要求 Gateway 在请求路径上承担更多**，而本记录刚刚给出了不把它设为默认的三条理由。

因此建议下一批**先补第 3 节那三件**（其中两件要另一个会话或时间），而不是在一个仍需显式开启的组件上叠加故障转移逻辑。
